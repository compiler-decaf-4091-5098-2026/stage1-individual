# Примеры для этапа 1

После `./build.sh` используйте `./run.sh --debug examples/<имя>.decaf` для дерева,
`./run.sh -t scan examples/<имя>.decaf` — для токенов.

## Успешный разбор

| Файл | Проверяет |
|---|---|
| `minimal.decaf` | Пустую функцию |
| `variables.decaf` | Объявления простых переменных |
| `expressions.decaf` | Арифметику, скобки и приоритеты |
| `assignments.decaf` | Присваивания, инкремент, декремент, унарный минус |
| `comparisons.decaf` | Сравнения и булевы литералы |
| `logic.decaf` | `&&`, `||`, `!` |
| `arrays.decaf` | Глобальные и локальные массивы, индексирование, `len`, приведения |
| `functions.decaf` | Импорт, параметры, вызовы, возвращаемые значения |
| `control-flow.decaf` | `if/else`, `for`, `while`, `break`, `continue` |
| `literals.decaf` | Десятичные и hex-числа, `long`, символы, строки, escapes и комментарии |
| `syntax-only.decaf` | Синтаксически допустимую программу с ошибками семантики этапа 2 |

Все эти файлы должны возвращать код 0 в режиме `parse`.

## Намеренные ошибки

`invalid.decaf` — отсутствует закрывающая скобка.
`invalid-token.decaf` — недопустимый символ `@`.
Остальные `invalid-*.decaf` проверяют размеры массивов в виде выражений,
списки параметров, неполный `for`, объявление после оператора, неверные escape-
последовательности, незакрытые строки и комментарии, неверные символьные и hex-литералы.
Ожидается код 1. Каскадные сообщения парсера допустимы: их количество не фиксировано.

Режим `scan` проверяет только лексику: например, `invalid-array.decaf` успешно
сканируется, но не проходит синтаксический анализ. Файлы с ошибками литералов,
комментариев или недопустимыми символами отклоняются уже при сканировании.
